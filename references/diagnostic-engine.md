# Diagnostic engine

Diagnose only what changes the next lesson. Do not turn onboarding into an exam.

If the learner explicitly states zero knowledge of the subject, accept that evidence for placement and begin with an explain-first foundation. Test only transferable prerequisites when skipping them would materially improve or harm the lesson; do not test the subject merely to confirm zero knowledge.

## Build a prerequisite map

For the active capability, identify its immediate prerequisites and transferable abilities. Use the learner's authentic goal to design a tiny task that samples the most consequential prerequisite first.

Classify evidence—not the person—as:

- `demonstrated`: correct without material help;
- `partial`: useful reasoning with a consequential gap;
- `misconceived`: a stable incorrect model is visible;
- `unknown`: not tested or insufficient evidence;
- `blocked`: language, accessibility, tool, anxiety, or task-format friction prevented a fair test.

Self-report may guide question selection but never establishes mastery.

## Diagnostic sequence

1. State the practical target in the learner's language.
2. Give one authentic, low-stakes task or ask for an existing work sample.
3. Ask the learner to show reasoning when it is safe and useful; accept alternative valid representations.
4. Separate subject gaps from language, interface, confidence, or accessibility barriers.
5. Test only the nearest uncertain prerequisite.
6. Start instruction as soon as the next useful objective is known.

Avoid trivia, trick questions, broad placement exams, and repeated questions already answered by evidence. For children, keep diagnostics short, concrete, supportive, and age-appropriate.

## Adaptation decision

- If prerequisites are demonstrated, skip redundant teaching and increase task authenticity.
- If partial, use a short bridge and guided practice.
- If misconceived, elicit the prediction, use a counterexample, rebuild the model, then retest.
- If unknown, teach safely from the lowest consequential assumption.
- If blocked, remove the barrier before interpreting performance.

Record the observation, task, amount of help, confidence, and next decision. Never convert one result into a fixed label.

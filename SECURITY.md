# Security policy

## Supported versions

Security fixes are supported for the current `1.0.x` release line. Versions before `1.0.0` are unsupported. When a newer supported line is announced, this policy will be updated.

## Report a vulnerability privately

Use [GitHub Private Vulnerability Reporting](https://github.com/ahmed3bead/teach-me/security/advisories/new). Do not open a public issue for a suspected vulnerability.

A useful report includes:

- the affected version or commit;
- the relevant file, component, or workflow;
- clear reproduction steps or a minimal proof of concept;
- the expected and observed security impact;
- any safe mitigation already tested.

Do not include learner data, credentials, private curricula, private transcripts, copyrighted source material, or unrelated personal information. Minimize every example needed to reproduce the issue.

Maintainers aim to acknowledge a report within seven calendar days. Updates will follow when triage status, mitigations, or release plans materially change; no fixed resolution deadline is promised because severity and remediation complexity vary.

Ordinary teaching-quality, language, evidence, or educator-mode bugs belong in the [teaching failure issue template](.github/ISSUE_TEMPLATE/teaching-failure.yml), with personal and protected material removed.
